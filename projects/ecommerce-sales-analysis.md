# E-commerce Sales Analysis

**A Python data analysis project exploring sales performance, product categories, customer satisfaction, and delivery performance using Brazilian e-commerce data.**

[View the source code on GitHub](https://github.com/Sanan-yaqoob/sales-analysis)

---

## Project Overview

The aim of this project was to analyse e-commerce order data to understand business performance and identify patterns that could help a company make better decisions.
Rather than looking at sales figures alone, I combined order, customer, product, and review data to investigate several questions:

- How much order value was generated by delivered orders?
- How did order value change over time?
- Which Brazilian states generated the highest order value?
- Which product categories performed best?
- Were any high-volume product categories receiving relatively low customer reviews?
- Was there a relationship between delivery performance and customer review scores?

I used Python to clean and combine the datasets, calculate business metrics, aggregate results, save analysis tables, and create visualisations.

## Dataset

The project uses the Olist Brazilian e-commerce dataset, which contains information about orders, customers, products, reviews, and order items.

## Project Workflow

The analysis follows this workflow:

1. Load the six source datasets.
2. Convert relevant timestamp columns into datetime values.
3. Aggregate individual order items into order-level values.
4. Merge order values with customer and review information.
5. Calculate order value, delivery duration, delivery delay, and purchase month.
6. Filter for delivered orders when calculating the main business metrics.
7. Analyse monthly order value and state-level performance.
8. Analyse product category revenue and customer satisfaction.
9. Compare review scores with delivery performance.
10. Export the resulting tables and charts into the `outputs` directory.

## Loading and Preparing the Data

I created a `load_data()` function to load all six datasets and prepare the date columns.

```python
def load_data():
    orders = pd.read_csv(DATA / "olist_orders_dataset.csv")
    items = pd.read_csv(DATA / "olist_order_items_dataset.csv")
    customers = pd.read_csv(DATA / "olist_customers_dataset.csv")
    reviews = pd.read_csv(DATA / "olist_order_reviews_dataset.csv")
    products = pd.read_csv(DATA / "olist_products_dataset.csv")
    category_translation = pd.read_csv(
        DATA / "product_category_name_translation.csv"
    )

    dates = [
        "order_purchase_timestamp",
        "order_delivered_customer_date",
        "order_estimated_delivery_date",
    ]

    for col in dates:
        orders[col] = pd.to_datetime(
            orders[col], errors="coerce"
        )

    return (
        orders,
        items,
        customers,
        reviews,
        products,
        category_translation,
    )
```

Putting the loading logic into a function keeps the main analysis organised and makes it easier to reuse the loading process.
`pd.read_csv()` reads each CSV file into a Pandas DataFrame.
The `dates` list contains the three timestamp columns needed for the delivery analysis. The `for` loop converts each of them to a datetime format.
The argument `errors="coerce"` converts invalid or unparseable date values into `NaT` (Not a Time), rather than stopping execution with a parsing error.
This matters because datetime values allow me to subtract dates and calculate elapsed delivery times.
The function returns all six DataFrames so that `main()` can use them.

## Calculating Order Values

An order can contain multiple products, so I first aggregated the individual order items.

```python
order_values = items.groupby(
    "order_id", as_index=False
).agg(
    item_value=("price", "sum"),
    freight_value=("freight_value", "sum"),
    item_count=("order_item_id", "count"),
)
```

### Why this step matters

The items dataset operates at the order-item level, whereas I needed a summary at the order level.

- `groupby("order_id")` groups items belonging to the same order.
- `item_value=("price", "sum")` calculates the total product price for each order.
- `freight_value=("freight_value", "sum")` calculates the total freight charge for each order.
- `item_count=("order_item_id", "count")` counts the order-item records in each order.
- `as_index=False` keeps `order_id` as a normal column.

This produces one aggregated row per order in the `order_values` table.

## 8. Combining Orders, Customers, and Reviews

I then combined the order information with the aggregated order values, customer details, and review scores.

```python
df = (
    orders.merge(order_values, on="order_id", how="left")
    .merge(
        customers[
            ["customer_id", "customer_unique_id", "customer_state"]
        ],
        on="customer_id",
        how="left",
    )
    .merge(
        reviews[["order_id", "review_score"]],
        on="order_id",
        how="left",
    )
)
```
### Understanding the joins

**Orders and order values:** Both datasets contain `order_id`, so I used it to attach the calculated item and freight totals to each order.
**Customer information:** I used `customer_id` to add the customer's unique identifier and state. The state allows me to compare order value across Brazilian states.
**Review information:** I used `order_id` to attach customer review scores to the order records.

I selected only the customer and review columns required for the analysis rather than bringing every column into the combined DataFrame.
I used left joins (`how="left"`) so the rows from the orders table were retained even when matching information was missing from another dataset. A left join can still introduce missing values, which need to be considered during analysis.

## Creating Business Metrics

After combining the datasets, I calculated several metrics used throughout the project.

```python
df["total_order_value"] = (
    df["item_value"].fillna(0)
    + df["freight_value"].fillna(0)
)

df["delivery_days"] = (
    df["order_delivered_customer_date"]
    - df["order_purchase_timestamp"]
).dt.total_seconds() / 86400

df["delay_days"] = (
    df["order_delivered_customer_date"]
    - df["order_estimated_delivery_date"]
).dt.total_seconds() / 86400

df["delivered_late"] = df["delay_days"] > 0

df["purchase_month"] = (
    df["order_purchase_timestamp"]
    .dt.to_period("M")
    .astype(str)
)
```

### Total order value

I added item value and freight value to calculate the total order value used in this project.
`fillna(0)` replaces missing values in these two monetary columns with zero before addition.
This measure includes freight charges. It should not be confused with accounting revenue or profit: the analysis does not calculate product costs, operating expenses, refunds, or profitability.

### Delivery duration

I subtracted the purchase timestamp from the delivery timestamp. The result is a time duration.
`.dt.total_seconds()` converts that duration into seconds, and dividing by `86400` converts seconds into days.

### Delivery delay

I subtracted the estimated delivery date from the actual delivery date.

- A positive value means delivery occurred after the estimated date.
- A negative value means delivery occurred before the estimated date.
- A value of zero means delivery occurred on the estimated date.

The Boolean column `delivered_late` is `True` when `delay_days` is greater than zero.

### Purchase month

`.dt.to_period("M")` groups timestamps into calendar months, while `.astype(str)` converts the monthly periods into strings for grouping and charting.
This creates a month-level field that can be used to track changes over time.

## Calculating the Main Business Metrics

The main analysis focuses on delivered orders.

```python
delivered = df[
    df["order_status"] == "delivered"
].copy()

print(f"Delivered orders: {len(delivered):,}")
print(
    "Order value including freight: "
    f"R$ {delivered['total_order_value'].sum():,.2f}"
)
print(
    "Average order value: "
    f"R$ {delivered['total_order_value'].mean():,.2f}"
)
print(
    "Average review score: "
    f"{delivered['review_score'].mean():.2f}"
)
print(
    "Late delivery rate: "
    f"{delivered['delivered_late'].mean() * 100:.2f}%"
)
```

### Metrics explained

**Delivered orders:** `len(delivered)` counts the rows in the delivered-orders DataFrame. The code assumes the merged data represents one row per order; this is worth validating when extending the analysis.
**Order value including freight:** `.sum()` adds the total order values across delivered orders.
**Average order value:** `.mean()` calculates the average total order value per row in the delivered-orders DataFrame.
**Average review score:** `.mean()` calculates the mean of the available review scores. Missing review scores are excluded by Pandas' default mean behaviour.
**Late delivery rate:** Because `delivered_late` is a Boolean column, its mean represents the proportion of `True` values. Multiplying by 100 converts the proportion to a percentage.

These metrics provide a starting point for understanding order volume, transaction value, customer feedback, and delivery performance.

## Product Category Performance

The product category analysis starts with individual order items because the items table contains the prices needed to calculate product-level sales performance.

```python
category_items = items.merge(
    products[["product_id", "product_category_name"]],
    on="product_id",
    how="left",
)

category_items = category_items.merge(
    category_translation,
    on="product_category_name",
    how="left",
)
category_items["category"] = (
    category_items["product_category_name_english"]
    .fillna(category_items["product_category_name"])
    .fillna("unknown")
)
```

### Why I combined these datasets

The order items dataset contains `product_id` and `price`, but the category name is stored in the products dataset.
I merged those tables using `product_id` to attach product categories to individual items.
I then joined the category translation table to obtain English category names where available.
The `fillna()` calls provide a fallback:

1. Use the English category name when available.
2. Otherwise, use the original category name.
3. If both are missing, label the category as `unknown`.

This makes the category results easier to read and reduces the number of missing category labels.

### Filtering to delivered orders

```python
delivered_info = delivered[
    ["order_id", "review_score"]
]

category_items = category_items.merge(
    delivered_info,
    on="order_id",
    how="inner",
)
```
The inner join keeps only category items whose order IDs appear in the delivered-orders dataset. It also adds review scores for the category satisfaction analysis.

### Calculating category performance

```python
category_performance = category_items.groupby(
    "category", as_index=False
).agg(
    orders=("order_id", "nunique"),
    items_sold=("product_id", "count"),
    revenue=("price", "sum"),
    average_item_price=("price", "mean"),
)
```

For each category, I calculated:

- `orders`: the number of unique delivered orders containing the category.
- `items_sold`: the number of item rows associated with the category.
- `revenue`: the sum of item prices.
- `average_item_price`: the mean item price.

One important distinction is that this category revenue measure uses `price` only. Unlike the overall order-value metric, it does not include freight.
I calculated average reviews separately to avoid counting the same order-category combination multiple times.

```python
category_reviews = (
    category_items[
        ["order_id", "category", "review_score"]
    ]
    .drop_duplicates()
    .groupby("category", as_index=False)
    .agg(
        average_review=("review_score", "mean")
    )
)
category_performance = category_performance.merge(
    category_reviews,
    on="category",
    how="left",
)
category_performance = category_performance.sort_values(
    "revenue", ascending=False
)
category_performance.to_csv(
    OUT / "category_performance.csv",
    index=False,
)
```
`drop_duplicates()` removes repeated order-category-review combinations before calculating average reviews. This is important when a single order contains multiple products in the same category.
I then merged the review averages into the category performance table, sorted categories by revenue.

## High-Revenue Categories With Lower Customer Satisfaction

A category can generate substantial sales while still receiving relatively low customer ratings. I investigated this by focusing on categories with at least 500 orders.

```python
eligible_categories = category_performance[
    category_performance["orders"] >= 500
].copy()
```
The minimum-order threshold helps avoid drawing conclusions from categories with very few orders. It does, however, mean that the results apply to the eligible categories rather than every category in the dataset.

### Calculating a review benchmark

```python
category_order_reviews = (
    category_items[
        ["order_id", "category", "review_score"]
    ]
    .drop_duplicates()
)
eligible_reviews = category_order_reviews.merge(
    eligible_categories[["category"]],
    on="category",
    how="inner",
)
overall_review = eligible_reviews["review_score"].mean()
```

I removed duplicate order-category-review combinations and restricted the benchmark calculation to the eligible categories.
The resulting `overall_review` is the average review score across the eligible order-category combinations. It is not necessarily the same as the average review across all delivered orders because an order containing multiple categories can contribute to multiple category-level observations.

### Measuring the review gap

```python
eligible_categories["review_gap"] = (
    eligible_categories["average_review"] - overall_review
)
low_satisfaction = eligible_categories.sort_values(
    "average_review", ascending=True
)
low_satisfaction.to_csv(
    OUT / "category_customer_satisfaction.csv",
    index=False,
)
```

The `review_gap` measures how far each category's average review sits above or below the benchmark.

- A negative review gap means the category's average review is below the benchmark.
- A positive review gap means it is above the benchmark.
- A value close to zero means it is close to the benchmark.

I sorted the eligible categories by average review in ascending order to bring the lowest-rated categories to the top.

### Visualising the lowest-rated categories

```python
bottom_categories = low_satisfaction.head(10).sort_values(
    "average_review", ascending=True
)
plt.figure(figsize=(12, 6))
sns.barplot(
    data=bottom_categories,

plt.axvline(

)

plt.title("Lowest-Rated Product Categories")
plt.xlabel("Average Review Score (out of 5)")
plt.ylabel("Product Category")
plt.xlim(0, 5)
plt.legend()
plt.tight_layout()
plt.savefig(OUT / "lowest_rated_categories.png", dpi=300)
plt.show()

```

The bars show the average review scores for the ten lowest-rated eligible categories. The dashed vertical line represents the review benchmark.
This makes it easier to spot categories that may deserve further investigation. Low reviews alone do not explain why customers were dissatisfied, so these results should be treated as a starting point for further analysis rather than proof of a specific problem.

## Review Scores and Delivery Performance

Finally, I grouped delivered orders by review score to investigate whether delivery duration and late-delivery rates differed across rating levels.

```python
review_delivery = delivered.groupby(
    "review_score", as_index=False
).agg(
    average_delivery_days=("delivery_days", "mean"),
    late_rate=("delivered_late", "mean"),
    orders=("order_id", "nunique"),
)
review_delivery["late_rate_pct"] = (
    review_delivery["late_rate"] * 100
)
review_delivery.to_csv(
    OUT / "review_delivery.csv", index=False
)
print("\nReview and delivery analysis:")
print(review_delivery.to_string(index=False))
```

### Understanding the results table

For each review score, I calculated:

- `average_delivery_days`: the average number of days between purchase and delivery.
- `late_rate`: the proportion of orders delivered after their estimated date.
- `orders`: the number of unique order IDs in the group.
- `late_rate_pct`: the late-delivery proportion converted into a percentage.

I used the review score as the grouping variable so I could compare delivery performance across rating levels.
This analysis can reveal patterns worth investigating, such as whether lower review scores tend to occur alongside longer delivery times or higher late-delivery rates.
However, a relationship between review scores and delivery metrics does not establish that late delivery caused a lower review. Product quality, customer service, and other factors could also influence customer satisfaction.
The resulting table is exported to `review_delivery.csv`.

## Limitations and Potential Improvements

Several improvements could make the analysis more robust.

### Data quality and missing values

The script converts invalid dates to missing datetime values and fills missing item and freight values with zero. These choices allow calculations to proceed, but missing data should also be measured and investigated because a missing amount is not always equivalent to zero.

### Review and merge validation

The analysis uses joins between several datasets. I could improve reliability by checking key uniqueness, validating expected join relationships, and measuring how many rows and missing values each merge introduces.

The main metrics also assume that the combined DataFrame represents one row per order. This should be explicitly checked before treating row counts and averages as definitive order-level metrics.

### Revenue definition

The overall order-value measure includes freight, while product category revenue sums product prices only. These are different measures and should be labelled clearly when comparing results.
Neither measure is profit, because costs and other financial adjustments are not included.

### Delivery analysis

The delivery calculations depend on valid purchase, actual delivery, and estimated delivery timestamps. I could add checks for missing dates and implausible durations before interpreting the averages and late-delivery rates.
